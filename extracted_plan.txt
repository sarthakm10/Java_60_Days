Q: What is the difference between == and .equals() for String?
== compares references (memory address). .equals() compares character content. New String("abc") == new String("abc") is false, but .equals() is true. String literals use the pool so "abc" == "abc" can be true. Always use .equals() for content comparison.

--- TABLE 6 ---
Q: Explain method overloading vs overriding. What are the rules?
Overloading: same name, different parameters, resolved at compile time (static polymorphism). Overriding: same signature in subclass, resolved at runtime (dynamic polymorphism). Rules for overriding: cannot reduce visibility, cannot throw broader checked exceptions, return type must be same or covariant, cannot override static/final/private methods.

--- TABLE 7 ---
Q: What is the purpose of the 'transient' keyword?
Marks a field to be excluded from Java serialization. When an object is serialized, transient fields are not written to the stream. On deserialization, they get their default values (null for objects, 0 for numbers, false for boolean). Used for sensitive data (passwords) or non-serializable fields.

Q: What are Java Records and when do you use them?
Records (Java 16+) are immutable data classes. The compiler auto-generates constructor, getters, equals, hashCode, toString. Use for DTOs, value objects, or any class that simply holds data. Example: record Point(int x, int y) {} ΓÇö you get Point.x(), Point.y(), equals(), hashCode() and toString() for free. They cannot extend other classes (implicitly extend Record) but can implement interfaces.

--- TABLE 13 ---
Q: What is the difference between synchronized and ReentrantLock?
synchronized is simpler but limited: JVM manages lock, no timeout, no condition variables, not interruptible. ReentrantLock is explicit: tryLock(timeout), lockInterruptibly(), multiple Condition objects (await/signal), fairness policy option. Use ReentrantLock when you need timed locks, interruptible locking, or multiple wait sets. synchronized is preferred for simple cases (less error-prone, JVM can optimize).

--- TABLE 14 ---
Q: Explain CompletableFuture and its advantages over Future.
Future.get() blocks the calling thread. CompletableFuture supports non-blocking: thenApply (transform result), thenAccept (consume result), thenCombine (combine two futures), exceptionally (handle errors), allOf/anyOf (coordinate multiple futures). It enables functional-style async pipelines and can be completed manually. Much more powerful for reactive-style code without blocking.

Collection Hierarchy Quick Reference

--- TABLE 18 ---
Q1: What is the internal data structure of ArrayList?
ArrayList uses a dynamic resizable array (Object[]). Default capacity is 10. When full, it creates a new array of 1.5x the size and copies all elements. Random access is O(1). Insert/delete in middle is O(n) due to shifting.

--- TABLE 19 ---
Q2: When does ArrayList resize and what is the growth factor?
When size == capacity and you add a new element. Growth formula: newCapacity = oldCapacity + (oldCapacity >> 1), effectively 1.5x. Use ensureCapacity(n) or new ArrayList<>(initialCapacity) to avoid frequent resizing for known large datasets.

--- TABLE 20 ---
Q3: ArrayList vs LinkedList ΓÇö when to use which?
ArrayList: faster random access O(1), better cache locality, less memory overhead. Use for frequent reads. LinkedList: faster add/remove at head/tail O(1), implements Deque so usable as stack/queue. Use when frequent insertions/deletions at both ends. LinkedList uses more memory (node pointers).

--- TABLE 21 ---
Q4: Is ArrayList thread-safe? How to make it thread-safe?
Not thread-safe. Options: 1) Collections.synchronizedList(new ArrayList<>()) ΓÇö wraps each method in synchronized block. 2) CopyOnWriteArrayList ΓÇö creates a fresh copy on every write, reads never block; ideal for read-heavy scenarios. 3) Use Vector (legacy, not recommended).

--- TABLE 22 ---
Q5: What happens if you modify a List while iterating with a for-each loop?
ConcurrentModificationException is thrown. The iterator checks a modCount field. Use Iterator.remove() for safe removal during iteration, or use removeIf() lambda, or iterate a copy, or use CopyOnWriteArrayList.

--- TABLE 23 ---
Q6: How does contains() work in ArrayList vs LinkedList?
Both use O(n) linear scan calling equals(). ArrayList has better cache performance. Use a HashSet for O(1) contains checks when that's the primary operation.

--- TABLE 24 ---
Q7: What is the difference between remove(int index) and remove(Object o) in ArrayList?
remove(int index) removes element at that position, O(n) due to shifting. remove(Object o) removes first occurrence by equals(), also O(n). Be careful with Integer: list.remove(1) calls remove(int), list.remove(Integer.valueOf(1)) calls remove(Object).

--- TABLE 25 ---
Q8: How to sort an ArrayList?
Collections.sort(list) ΓÇö uses merge sort (TimSort), O(n log n), stable. list.sort(Comparator) ΓÇö Java 8+. For custom objects: list.sort(Comparator.comparing(Employee::getSalary).thenComparing(Employee::getName)).

--- TABLE 26 ---
Q9: What is the time complexity of get(), add(), remove() in LinkedList?
get(index) is O(n) ΓÇö traverses from head or tail (whichever is closer). add()/addLast() O(1). addFirst() O(1). remove() from middle O(n) to find, O(1) to unlink. This is why LinkedList is rarely the best choice for indexed access.

--- TABLE 27 ---
Q10: How does subList() work in ArrayList?
subList(from, to) returns a view (not a copy) of the original list. Changes to the subList reflect in the original and vice versa. If the original list is structurally modified after subList(), a ConcurrentModificationException will be thrown on subList access. To get an independent copy: new ArrayList<>(list.subList(1, 4)).

--- TABLE 28 ---
Q11: What is Collections.unmodifiableList() and when to use it?
Returns a view that throws UnsupportedOperationException on mutation operations. Note: the underlying list can still be modified by the original reference ΓÇö it only prevents modification via the unmodifiable view. For truly immutable: List.of() (Java 9+) or List.copyOf() ΓÇö null-free, truly immutable.

--- TABLE 29 ---
Q12: Explain the difference between Arrays.asList() and List.of().
Arrays.asList(): fixed-size but mutable (set allowed, add/remove not); backed by array; allows nulls; returns java.util.Arrays$ArrayList. List.of() (Java 9+): completely immutable (no set/add/remove); does NOT allow nulls; not backed by an array. For most modern code, prefer List.of() for constants.

--- TABLE 30 ---
Q13: How does HashMap work internally in Java 8+?
Uses array of Node<K,V> buckets. Index = hash(key) & (capacity-1). Each bucket holds a linked list; when bucket size > 8 and table size >= 64, it converts to a Red-Black Tree (treeify) for O(log n) worst case. Default capacity 16, load factor 0.75. When size > capacity * loadFactor, it doubles and rehashes.

--- TABLE 31 ---
Q14: What happens when two keys have the same hashCode?
Hash collision: both entries go to the same bucket and form a linked list (chaining). Retrieval: traverse the list calling equals() to find the right key. This is why overriding hashCode() alone is not enough ΓÇö equals() must also be consistent.

--- TABLE 32 ---
Q15: Why must you override both hashCode() and equals() together?
Contract: if a.equals(b) is true, then a.hashCode() == b.hashCode() MUST be true. If you override only equals(), two equal objects can land in different buckets ΓÇö HashMap will never find the value. If you override only hashCode(), objects in the same bucket won't match via equals() ΓÇö duplicates can be inserted.

--- TABLE 33 ---
Q16: What is the load factor in HashMap and how does it affect performance?
Load factor = size/capacity threshold for rehashing. Default 0.75 balances memory vs time. Lower load factor (e.g., 0.5): fewer collisions, more memory, more frequent resizing. Higher (e.g., 0.9): more collisions, less memory. HashMap(initialCapacity, loadFactor) for tuning.

--- TABLE 34 ---
Q17: HashMap vs LinkedHashMap vs TreeMap ΓÇö differences?
HashMap: O(1) average, no order guarantee. LinkedHashMap: O(1), maintains insertion order (or access order for LRU cache). TreeMap: O(log n), sorted by natural order or Comparator. Use TreeMap for sorted key access, LinkedHashMap for ordered iteration or LRU cache.

--- TABLE 35 ---
Q18: How to implement an LRU Cache using LinkedHashMap?
Extend LinkedHashMap with accessOrder=true in constructor, override removeEldestEntry() to return true when size > maxSize. Example: new LinkedHashMap<>(capacity, 0.75f, true) { protected boolean removeEldestEntry(Map.Entry<K,V> e) { return size() > maxSize; } }

--- TABLE 36 ---
Q19: What is ConcurrentHashMap and how is it thread-safe?
Uses segment-level (Java 7) or bucket-level CAS+synchronized (Java 8+) locking. In Java 8, only the affected bucket is locked during write, allowing higher concurrency. Read operations are non-blocking. Null keys and values are NOT allowed (unlike HashMap). computeIfAbsent(), merge() are atomic operations.

--- TABLE 37 ---
Q20: HashMap vs Hashtable vs ConcurrentHashMap?
Hashtable: legacy, synchronizes every method (entire map), slow, no nulls. HashMap: not thread-safe, allows one null key. ConcurrentHashMap: fine-grained locking, high concurrency, no null keys/values. Always prefer ConcurrentHashMap over Hashtable. Never use Hashtable in new code.

--- TABLE 38 ---
Q21: What is the worst case time complexity for HashMap?
O(n) in Java 7 (all keys in same bucket as linked list). O(log n) in Java 8+ when bucket is treeified. Caused by hash collision attacks or poor hashCode implementations. This is why Java 8 introduced treeification.

--- TABLE 39 ---
Q22: Can we use a mutable object as a HashMap key?
Technically yes, but strongly discouraged. If the key's fields change after insertion, hashCode() changes, the key falls in a different bucket, and you can never retrieve the value. Best practice: use immutable objects (String, Integer, custom immutable classes) as keys.

--- TABLE 40 ---
Q23: What is HashMap's behavior with null keys?
HashMap allows exactly one null key, stored at bucket index 0. Hashtable and ConcurrentHashMap do NOT allow null keys. TreeMap does not allow null keys (NullPointerException on comparison).

--- TABLE 41 ---
Q24: Explain Map.Entry and how to iterate a HashMap.
Map.Entry is an inner interface representing a key-value pair. Iteration options: 1) entrySet() for-each (most efficient). 2) keySet() then get(key) (two lookups, less efficient). 3) values() to iterate only values. 4) forEach((k,v) -> ...) with Java 8 lambda. Always prefer entrySet() for key+value iteration.

--- TABLE 42 ---
Q25: What is getOrDefault(), putIfAbsent(), computeIfAbsent()?
getOrDefault(key, default): returns value or default without inserting. putIfAbsent(key, val): inserts only if key absent, thread-safe in ConcurrentHashMap. computeIfAbsent(key, fn): inserts fn.apply(key) if absent, returns existing or new value. Great for building Map<K, List<V>>: map.computeIfAbsent(key, k -> new ArrayList<>()).add(value).

--- TABLE 43 ---
Q26: How does HashMap handle rehashing?
When size exceeds capacity * loadFactor, capacity doubles. All existing entries are rehashed (new index = hash & newCapacity-1). This is O(n) operation. In Java 8, optimization: entries either stay at same index or move to index + oldCapacity ΓÇö no need to recompute hash for each entry during resize.

--- TABLE 44 ---
Q27: What is WeakHashMap and when to use it?
Uses WeakReferences for keys. When a key has no strong references outside the map, GC can collect it, and the entry is automatically removed. Use case: caches, metadata about objects where the map shouldn't prevent GC. ThreadLocal's internal implementation uses a WeakReference for thread-to-value mapping.

--- TABLE 45 ---
Q28: How to make a HashMap thread-safe without ConcurrentHashMap?
1) Collections.synchronizedMap(new HashMap<>()) ΓÇö synchronized on the entire map, all operations locked. Must manually synchronize iteration: synchronized(map) { for (Map.Entry e : map.entrySet()) {...} }. 2) ConcurrentHashMap is almost always better ΓÇö higher concurrency.

--- TABLE 46 ---
Q29: What is EnumMap and why is it faster than HashMap for enum keys?
EnumMap uses a plain array indexed by the enum's ordinal. O(1) access with no hashing needed, no collision handling, extremely memory efficient. Always use EnumMap when keys are an enum type. EnumSet similarly uses a bitmask for O(1) operations.

--- TABLE 47 ---
Q30: Explain TreeMap's internal data structure and ordering.
TreeMap uses a Red-Black Tree (self-balancing BST). All operations (get, put, remove) are O(log n). Keys must implement Comparable or you must provide a Comparator. headMap(), tailMap(), subMap(), floorKey(), ceilingKey() are powerful range operations unavailable in HashMap.

--- TABLE 48 ---
Q31: How does HashSet work internally?
HashSet is backed by a HashMap. When you add(element), it calls map.put(element, PRESENT) where PRESENT is a static dummy Object. All HashMap rules apply: hashCode() + equals() determines uniqueness. Contains() is O(1) average.

--- TABLE 49 ---
Q32: HashSet vs LinkedHashSet vs TreeSet?
HashSet: O(1) add/remove/contains, no order. LinkedHashSet: O(1), maintains insertion order. TreeSet: O(log n), sorted natural order or Comparator, implements NavigableSet. Use TreeSet for sorted unique elements, or when you need floor/ceiling/headSet/tailSet operations.

--- TABLE 50 ---
Q33: How to remove duplicates from a List while preserving order?
new LinkedHashSet<>(list) preserves insertion order and removes duplicates. Then new ArrayList<>(linkedHashSet) to convert back. Java 8: list.stream().distinct().collect(Collectors.toList()) also works (uses equals/hashCode).

--- TABLE 51 ---
Q34: What are Set operations: union, intersection, difference?
Union: Set<T> union = new HashSet<>(setA); union.addAll(setB). Intersection: Set<T> inter = new HashSet<>(setA); inter.retainAll(setB). Difference: Set<T> diff = new HashSet<>(setA); diff.removeAll(setB). These mutate the copy, not the originals.

--- TABLE 52 ---
Q35: Can HashSet contain null?
HashSet can contain one null (since HashMap allows one null key). TreeSet cannot contain null (comparison would throw NPE). LinkedHashSet can contain one null. ConcurrentSkipListSet cannot contain null.

--- TABLE 53 ---
Q36: What is CopyOnWriteArraySet?
Backed by a CopyOnWriteArrayList. Thread-safe, all mutating operations create a new copy of the internal array. Reads are non-blocking. Suitable for small sets with infrequent writes and frequent reads/iterations. High memory overhead for write-heavy scenarios.

--- TABLE 54 ---
Q37: How does TreeSet handle custom sorting?
Pass a Comparator to the constructor: new TreeSet<>(Comparator.comparing(Employee::getSalary)). The comparator defines BOTH ordering and equality for TreeSet ΓÇö if compareTo returns 0, elements are considered equal (duplicate) even if equals() says different. This can cause surprising deduplication!

--- TABLE 55 ---
Q38: What is NavigableSet and its key methods?
NavigableSet (TreeSet implements it): floor(e) ΓÇö greatest element <= e; ceiling(e) ΓÇö least element >= e; lower(e) ΓÇö strictly less; higher(e) ΓÇö strictly greater; pollFirst()/pollLast() ΓÇö retrieve and remove. descendingSet() ΓÇö reverse view. Very useful for range-based problems.

--- TABLE 56 ---
Q39: How does equals() and hashCode() affect Set behavior?
If two objects are equal (equals() returns true), they must have the same hashCode(). Adding both to a HashSet will result in only one entry. If hashCode() is inconsistent (returns different values for equal objects), both will be added ΓÇö breaking the Set contract. Always generate both methods together (IDE or Lombok @EqualsAndHashCode).

--- TABLE 57 ---
Q40: What is a BitSet and when would you use it?
BitSet is a memory-efficient set of bits (booleans). Operations: set(index), get(index), and(), or(), xor(), cardinality() (count of set bits). Use for large boolean arrays, sieve of Eratosthenes, flags, bloom filters, and anywhere you need a compact representation of a set of integers.

--- TABLE 58 ---
Q41: What is the difference between Queue methods: add/offer, remove/poll, element/peek?
add() throws exception if queue full; offer() returns false. remove() throws NoSuchElementException if empty; poll() returns null. element() throws if empty; peek() returns null. Always prefer offer/poll/peek for safer code. These pairs exist for bounded vs unbounded queues.

--- TABLE 59 ---
Q42: When to use ArrayDeque vs LinkedList as a Stack/Queue?
ArrayDeque is faster and has better memory locality (no node overhead). Implements Deque, works as both stack (push/pop) and queue (offer/poll). LinkedList has null support and implements List too, but is slower. Java docs recommend ArrayDeque over Stack class. Stack class is legacy (extends Vector).

--- TABLE 60 ---
Q43: How does PriorityQueue work?
Min-heap by default (smallest element at head). Internally uses an array-based binary heap. offer()/add() and poll() are O(log n). peek() is O(1). For max-heap: new PriorityQueue<>(Collections.reverseOrder()). For custom: new PriorityQueue<>(Comparator.comparing(Task::getPriority)). Contains() is O(n).

--- TABLE 61 ---
Q44: What is BlockingQueue and its common implementations?
BlockingQueue blocks on take() if empty, and put() if full ΓÇö used for producer-consumer patterns. ArrayBlockingQueue: bounded, backed by array. LinkedBlockingQueue: optionally bounded. PriorityBlockingQueue: unbounded, ordered. DelayQueue: elements available after delay. SynchronousQueue: no internal buffer, handoff between threads.

--- TABLE 62 ---
Q45: How to implement a producer-consumer using BlockingQueue?
Producer: queue.put(item) ΓÇö blocks if full. Consumer: item = queue.take() ΓÇö blocks if empty. No manual synchronization needed. Example: BlockingQueue<Task> queue = new LinkedBlockingQueue<>(100). This is the standard pattern for thread pools and async task processing.

--- TABLE 63 ---
Q46: Difference between Deque and Queue?
Queue is single-ended (FIFO). Deque (double-ended queue) supports add/remove at both ends. As stack: push()/pop() at head. As queue: offer()/poll() at tail/head. ArrayDeque implements Deque and is the recommended implementation. LinkedList also implements Deque but slower.

--- TABLE 64 ---
Q47: What is ConcurrentLinkedQueue?
Non-blocking, thread-safe queue using CAS (Compare-And-Swap) operations. No locking ΓÇö very high throughput. Does not support blocking (use LinkedBlockingQueue for blocking). size() is O(n) ΓÇö not constant time. Best for high-throughput, non-blocking concurrent access.

--- TABLE 65 ---
Q48: How to find the kth largest element using a PriorityQueue?
Maintain a min-heap of size k. Iterate all elements: if current > heap.peek(), poll and offer current. After full iteration, heap.peek() is the kth largest. Time: O(n log k). More efficient than sorting: O(n log n). This pattern appears frequently in top-k problems.

--- TABLE 66 ---
Q49: What is a monotonic stack and when is it useful?
A stack that maintains elements in strictly increasing or decreasing order. As you push, pop elements that violate the monotonic property. Use for: next greater element, next smaller element, largest rectangle in histogram, stock span problems. Time complexity: O(n) because each element is pushed and popped at most once.

--- TABLE 67 ---
Q50: Explain TransferQueue and its use case.
TransferQueue (implemented by LinkedTransferQueue) extends BlockingQueue. Key method: transfer(e) ΓÇö blocks until a consumer takes the element (unlike put() which just adds to the queue). tryTransfer(e) returns immediately. Use when the producer needs confirmation that a consumer has received the item.

--- TABLE 68 ---
Q51: What is the difference between Comparable and Comparator?
Comparable: implemented by the class itself, defines natural ordering via compareTo(). Single ordering only. Comparator: external, defines custom ordering via compare(). Multiple orderings possible. Comparator.comparing() chains: Comparator.comparing(Person::getAge).thenComparing(Person::getName). Use Comparable for one canonical order, Comparator for flexibility.

--- TABLE 69 ---
Q52: How does Collections.sort() decide the order for a custom class?
Either the class implements Comparable (natural order), or you pass a Comparator. If neither, ClassCastException at runtime. list.sort(null) uses Comparable. Internally uses TimSort ΓÇö O(n log n) stable sort, efficient on partially sorted data.

--- TABLE 70 ---
Q53: What is fail-fast vs fail-safe iterator?
Fail-fast: throws ConcurrentModificationException if the collection is structurally modified during iteration (ArrayList, HashMap iterators). Checks modCount. Fail-safe: iterates on a snapshot/copy, no exception (CopyOnWriteArrayList, ConcurrentHashMap). Fail-safe uses more memory, may not reflect latest changes.

--- TABLE 71 ---
Q54: What does Collections.frequency() do?
Returns the number of times an element appears in a collection using equals(). Example: Collections.frequency(list, "java"). For Map, use Collectors.groupingBy + Collectors.counting() in streams. Also useful: Collections.disjoint(c1, c2) ΓÇö true if no common elements.

--- TABLE 72 ---
Q55: Explain Collections.binarySearch() requirements and behavior.
The list MUST be sorted. Returns index of element if found; otherwise -(insertion point) - 1. Uses Comparable or Comparator. Only works correctly on sorted RandomAccess lists (ArrayList). For LinkedList it works but is O(n) due to linear traversal. Always sort before binary search.

--- TABLE 73 ---
Q56: What is the difference between Collections.emptyList() and List.of()?
Collections.emptyList(): returns a shared singleton empty list, mutable type signature but throws on add. List.of() (Java 9+): creates a truly immutable, null-free list. For non-empty lists use List.of(a,b,c). Prefer List.of() in modern Java for clarity and immutability guarantees.

--- TABLE 74 ---
Q57: How does Collections.nCopies() work?
Returns an immutable List of n copies of the specified object ΓÇö all elements share the same reference. Good for initializing lists. Example: Collections.nCopies(5, 0) returns [0,0,0,0,0]. Note: since it's immutable, you can't add/remove. Use new ArrayList<>(Collections.nCopies(n, val)) for mutable version.

--- TABLE 75 ---
Q58: Explain the use of Collections.checkedCollection().
Returns a dynamically type-safe view. At runtime, throws ClassCastException if you try to add wrong type. Useful to track down heap pollution from raw types or unchecked casts. Example: Collections.checkedList(rawList, String.class) ΓÇö every add is type-checked at runtime.

--- TABLE 76 ---
Q59: What are the SOLID principles and how do they apply to Collections usage?
S: Single Responsibility ΓÇö collection should have one purpose. O: Open/Closed ΓÇö use interface types (List, Map) not implementations. L: Liskov ΓÇö ArrayList/LinkedList can substitute List. I: Interface Segregation ΓÇö use the most specific interface needed (List vs Collection). D: Dependency Inversion ΓÇö depend on List<T> not ArrayList<T> in method signatures.

--- TABLE 77 ---
Q60: How to create an immutable collection in Java 9+?
List.of(1,2,3), Set.of("a","b"), Map.of("k1","v1","k2","v2"). Also: Map.copyOf(existingMap), List.copyOf(existingList). These are null-free and throw UnsupportedOperationException on mutation. For ordered Map: use Map.ofEntries(Map.entry(k,v), ...).

--- TABLE 78 ---
Q61: What is ConcurrentHashMap's compute() method?
compute(key, remappingFn) atomically applies the function to the current value (or null if absent) and replaces it. If fn returns null, the key is removed. Atomic ΓÇö no external synchronization needed for read-modify-write patterns like counting: map.compute(word, (k,v) -> v == null ? 1 : v+1).

--- TABLE 79 ---
Q62: Explain the merge() method of Map.
map.merge(key, value, (oldVal, newVal) -> merged) ΓÇö if key absent, inserts value; if present, applies the merge function. Perfect for aggregation: map.merge(word, 1, Integer::sum) ΓÇö word frequency counting in one line. If merge function returns null, key is removed.

--- TABLE 80 ---
Q63: What is CopyOnWriteArrayList and its performance trade-offs?
On every add/set/remove, a new copy of the internal array is created. Reads (get, iterator, size) are lock-free and never throw ConcurrentModificationException. Write operations are O(n). Best for: event listener lists, rarely-modified read-heavy collections. Avoid for write-heavy scenarios.

--- TABLE 81 ---
Q64: How does ConcurrentSkipListMap work?
Thread-safe, sorted map using skip list data structure. O(log n) operations. Alternative to synchronized TreeMap. Supports concurrent reads and writes without locking entire structure. Key-value iteration in sorted order. Use when you need a concurrent sorted map.

--- TABLE 82 ---
Q65: What is the difference between HashMap and IdentityHashMap?
IdentityHashMap uses == (reference equality) instead of equals() for key comparison, and System.identityHashCode() instead of hashCode(). Two distinct objects with same content are treated as different keys. Use case: object graph traversal where you need to track specific instances (serialization, deep copy).

--- TABLE 83 ---
Q66: How to sort a Map by value?
entrySet().stream().sorted(Map.Entry.comparingByValue()).collect(Collectors.toMap(Map.Entry::getKey, Map.Entry::getValue, (e1,e2)->e1, LinkedHashMap::new)). LinkedHashMap preserves insertion order, maintaining the sorted order. For reverse: Map.Entry.comparingByValue(Comparator.reverseOrder()).

--- TABLE 84 ---
Q67: What is a Deque and how does ArrayDeque replace Stack?
Deque = double-ended queue. ArrayDeque.push(e) = addFirst(e), pop() = removeFirst(). Much faster than Stack (no synchronization). Stack is a legacy class extending Vector. Java docs explicitly recommend ArrayDeque as a stack. ArrayDeque is also faster than LinkedList as a queue.

--- TABLE 85 ---
Q68: How to implement a thread-safe counter without synchronized?
Use AtomicInteger: AtomicInteger counter = new AtomicInteger(0); counter.incrementAndGet(); counter.compareAndSet(expected, update). CAS-based, no locking, very fast. LongAdder is even faster for high-contention counters ΓÇö distributes increments across cells, reduces contention.

--- TABLE 86 ---
Q69: What are the differences between HashMap.forEach() and entrySet iteration?
map.forEach((k,v) -> ...) is cleaner, Java 8+, uses Consumer. entrySet() iteration is classic, allows break via iterator. forEach cannot throw checked exceptions easily. Both are O(n). ConcurrentHashMap.forEach() has additional parallelism threshold parameter for parallel execution.

--- TABLE 87 ---
Q70: How to find duplicate elements in a List efficiently?
Set<T> seen = new HashSet<>(); list.stream().filter(e -> !seen.add(e)).collect(Collectors.toList()) ΓÇö seen.add() returns false for duplicates. O(n) time and space. Alternative: Collections.frequency() for single element check. For count map: Collectors.groupingBy(Function.identity(), Collectors.counting()).

--- TABLE 88 ---
Q71: What is a SortedMap and NavigableMap?
SortedMap: extends Map, keys in sorted order, firstKey()/lastKey()/headMap/tailMap/subMap. NavigableMap extends SortedMap: adds floor/ceiling/lower/higher/descendingMap/pollFirstEntry/pollLastEntry. TreeMap implements NavigableMap. ConcurrentSkipListMap is the concurrent implementation.

--- TABLE 89 ---
Q72: How to group a List into a Map<K, List<V>> using Streams?
Collectors.groupingBy(classifier): map each element to a group key, collect values. Example: Map<String, List<Employee>> = list.stream().collect(Collectors.groupingBy(Employee::getDept)). With downstream collector: groupingBy(dept, Collectors.counting()) gives Map<String, Long>.

--- TABLE 90 ---
Q73: What is the difference between List.copyOf() and new ArrayList<>(existing)?
List.copyOf() returns an unmodifiable copy ΓÇö throws UnsupportedOperationException on mutation. new ArrayList<>(existing) creates a mutable copy. List.copyOf() also throws NullPointerException if source contains nulls. Use copyOf() when you want to expose a safe view to external callers.

--- TABLE 91 ---
Q74: How does PriorityBlockingQueue differ from PriorityQueue?
PriorityBlockingQueue is thread-safe and supports blocking take() operation ΓÇö blocks if empty. PriorityQueue is not thread-safe. PriorityBlockingQueue is unbounded (no put() blocking). Use in thread pool implementations and task scheduling where threads must wait for the highest-priority task.

--- TABLE 92 ---
Q75: What is the collections framework's relationship to Iterable and Iterator?
Iterable<T> requires iterator() method ΓÇö enables for-each loops. Iterator<T> has hasNext(), next(), remove(). Collections implement Iterable. For custom data structures: implement Iterable to support for-each, implement Iterator for traversal logic. ListIterator extends Iterator with hasPrevious/previous/add/set for bidirectional traversal.

--- TABLE 93 ---
Q76: How to efficiently find the intersection of two large lists?
Convert one list to HashSet (O(n)), then filter the other list using set.contains() (O(m)). Total: O(n+m) vs O(n*m) for nested loops. list1.stream().filter(new HashSet<>(list2)::contains).collect(Collectors.toList()). For sorted lists, two-pointer approach gives O(n+m) with O(1) space.

--- TABLE 94 ---
Q77: What is an ArrayBlockingQueue and its fairness parameter?
Bounded blocking queue backed by array. Constructor: ArrayBlockingQueue(capacity, fair). fair=true: threads acquire lock in FIFO order ΓÇö prevents starvation but reduces throughput. fair=false (default): no ordering guarantee, higher throughput. Use fair=true only when thread ordering is critical to correctness.

--- TABLE 95 ---
Q78: How to implement a simple cache with automatic expiry using collections?
Use LinkedHashMap with accessOrder=true + removeEldestEntry() for LRU. For time-based expiry: wrap values in a holder with timestamp, remove in background thread or lazy removal on access. Production alternative: Caffeine cache library ΓÇö high-performance caching with W-TinyLFU eviction policy.

--- TABLE 96 ---
Q79: What is Collections.rotate() and how does it work?
Collections.rotate(list, distance) ΓÇö rotates elements by distance positions. Positive: right rotation (last distance elements move to front). Negative: left rotation. Efficient implementation uses three reversal algorithm: O(n). Example use: shifting elements in circular buffer or implementing rotation problems.

--- TABLE 97 ---
Q80: How do Java's collection streams interact with short-circuit operations?
Short-circuit operations (findFirst, anyMatch, allMatch, noneMatch, limit) stop processing as soon as result is determined ΓÇö don't need to process all elements. findFirst() on parallel stream is O(1) effective. anyMatch(pred) returns true at first match. This makes streams efficient for search operations on large collections.

Q: Explain Kafka's delivery guarantees: at-most-once, at-least-once, exactly-once.
At-most-once: producer fire-and-forget, consumer auto-commit before processing ΓÇö possible message loss. At-least-once: producer retries with acks=all, consumer manual commit after processing ΓÇö possible duplicates. Exactly-once: requires idempotent producer (enable.idempotence=true) + transactional API + read_committed on consumer. EOS is expensive ΓÇö use at-least-once + idempotent consumers for most cases.

--- TABLE 115 ---
Q: What is consumer lag and how do you monitor it?
Consumer lag = latest offset (LEO) - consumer committed offset. High lag means consumers are behind. Monitor with: kafka-consumer-groups.sh --describe, Burrow (LinkedIn), or Prometheus JMX exporter + Grafana. CloudWatch has kafka_consumer_lag metric for MSK. Alert when lag exceeds threshold. Fix: increase partitions, add consumers (up to partition count), optimize processing.

Topic | Key Points to Know
Partition Rebalancing | Triggered when consumer joins/leaves group. Static membership (group.instance.id) reduces rebalancing in K8s.
Message Ordering | Guaranteed within a partition, not across partitions. Use same key for ordered messages. Keyed producer routes same key to same partition.
Compacted Topics | Only last value per key retained. Delete marker (null value) = tombstone. Good for state snapshots, reference data.
Kafka Transactions | Atomic produce to multiple topics/partitions. transactional.id, beginTransaction, commitTransaction, abortTransaction.
Kafka Streams | Stateless: map, filter, flatMap. Stateful: aggregate, join, windowing (tumbling, hopping, session windows). State stores backed by RocksDB + changelog topic.
MSK (AWS) | Managed Kafka. Auto-scaling storage, MSK Connect for connectors, MSK Serverless for variable workloads, CloudWatch integration.

Q: How do you ensure message ordering in Kafka?
Use a partition key ΓÇö all messages with the same key go to the same partition and are consumed in order. max.in.flight.requests.per.connection=1 ensures order even on retry (or use idempotent producer which handles this). If global ordering is needed across partitions, it means a single partition ΓÇö which limits throughput.

--- TABLE 118 ---
Q: What happens when a Kafka consumer crashes?
Consumer group coordinator detects missed heartbeats after session.timeout.ms. Triggers a rebalance ΓÇö partitions are redistributed to remaining consumers. With auto-commit, in-flight messages since last commit may be reprocessed. With manual commit, only after successful processing is offset committed ΓÇö reduces data loss but may cause duplicates on restart.
